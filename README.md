# BIPH 场地管理台 — 本地自托管篮球记分牌

替代 `scoreboard.best` 的校内自托管版本。**Docker 一条命令部署,跑在校园网里,计时器完全不依赖网络。**

---

## 为什么做这个

竞品(`scoreboard.best`)把剩余时间当作**格式化字符串**(`"07:22"`)随状态一起同步,大屏原样渲染、不做任何本地推算。
实测其前端 bundle 确认:

```js
// 大屏渲染:原样输出服务端下发的字符串
children: F.clock.timeRemaining
```

因此网络一抖,大屏就**滞后 → 冻结 → 跳变**。这不是网络慢,是数据模型错了。

BIPH 场地管理台 改用**锚点模型**:服务端只保存「在服务器时刻 T 还剩 R 毫秒且正在跑」这一个事实,客户端用本地单调时钟自己走秒。
消息自带时间戳 ⇒ 迟到、重复、乱序、丢失都不会算错;**断网期间大屏照常计时**。

| **比赛配置** | `/m/<id>/setup` | 队名 / 队色 / 队徽、规则参数(节数、每节分钟、进攻钟秒数、暂停次数与时长、BONUS 阈值)、开赛时间、显示设置;顶栏常驻保存状态 |

> **截图没有放进仓库**:`docs/screenshots/` 里是真实赛事的大屏截图(含真实赛事名、队名和渲染出来的队徽),
> 所以整目录在 `.gitignore` 里,仓库里一张都不带。整套界面截图在开发机的 `docs/screenshots/` 下。

- **大屏**:固定 1920×1080 设计画布,按屏幕等比缩放(不依赖任何 Web 字体,数字是自绘的七段数码管 SVG)
- **控制台**:横屏双栏 / 竖屏单栏自动重排,按钮 ≥64pt,主操作 ≥88pt
- **管理台**:一块场地一张卡,多场地并行监控,点进去是单场配置;每张卡带**运动项目 emoji**(篮球 🏀)
- **中/英切换**:四端都能切,而且**整个场馆一个语言** —— 在管理台、控制台、配置页或大屏角上切一下,**所有大屏、所有控制台、管理台一起变**(不用两台设备各点一次)。浏览器标签页标题也跟着换
- **请求暂停**:控制台每支队伍的比分区旁有独立的「请求暂停」按钮 —— 一次点击用掉一次暂停额度、自动停住比赛钟与进攻钟、让大屏进入暂停倒计时;**暂停时长在比赛配置页的规则参数里按本场调整**(默认 60 秒)。暂停中该队按钮变成实心橙色的 **「继续比赛」**,点了大屏回到比赛计时器、计时器保持停止
- **操作生效提示**:控制台右上角弹一条提示,告诉你刚才那一下**到底生效了没有** —— 加分、加犯规、启停计时、请求暂停、换边、撤销…… 全都提示。绿色对勾 = 真的生效了;红色 = **被服务器拒绝了**(比如暂停额度已用完),并直接告诉你原因。这条提示等的是**服务端的回执**,不是"我按了",所以不会出现"弹了绿勾但其实什么都没发生"
- **暂停倒计时提示**:暂停最后 5 秒,控制台顶部亮起**红色横幅**并逐秒读秒(「暂停倒计时 5 秒后结束」→ …→「1 秒后结束」);倒计时走完,横幅转成**绿色**「暂停时间结束,请准备开赛」,3 秒后自动撤下。判定在**浏览器本地**做(和计时器同一套锚点原理),所以**断网也准时**。提前按「继续比赛」不算"时间到",不会误弹
- **开赛时间与大屏开赛倒计时**:比赛配置页填一个**开赛时间**(`HH:MM`,赛程表上 19:00 那场),大屏就在**开赛前 3 分钟**整屏切到「距开赛 02:45」的大号七段管倒计时,附赛事名、计划开赛时间与场地号。判定在浏览器本地做,断网照常走;跨零点也算得对(23:58 配 00:30 指的是明天 00:30)。**离开赛还早时,大屏待机屏也直接写「19:00 开赛」**,不只写一句"即将开始"
- **落款**:大屏与管理台底部居中一行「本服务由 BIPH IT 部门提供」,灰色小字,随界面语言切换
- **队徽上大屏**:比赛配置页给主客两队各上传一个队徽(PNG/JPG,≤2MB),**上传完立刻出现在大屏上**,不用再去点「保存」;没队徽就不占位。队徽高度固定、宽度自适应,不会被拉变形;队名太长时省略的是队名,不是队徽
- **管理员密钥确认框**:点「重置比赛」/「删除比赛」弹窗要密钥(默认 `1818`),输错弹窗不关、原地报错
- **大屏暂停倒计时**:请求暂停后大屏整屏切到倒计时(卡片边框是请求方的队色,倒计时是七段数码管)
- **控制台墙钟**:左上角显示服务器当前时间(与管理台右上角同一个组件、同一个口径),走服务器时间估计,断网也照样走
- **破坏性操作要密钥**:「重置比赛」/「删除比赛」点下去会弹窗要管理员密钥(默认 `1818`);密钥输错弹窗不关,原地告诉你原因。**控赛与改本场参数不需要密钥**
- **墙钟**:管理台右上角那个**服务器当前时间**,控制台左上角也保留一份(同一个组件、同一个口径)。走服务器时间估计而不是 iPad 的系统时间 —— iPad 对不准表时,计分员靠这个对表;断网也照样走

## 快速开始

### 1. 部署(学校服务器)

```bash
git clone https://github.com/Alexie7777/BIPH-Scoreboard.git && cd BIPH-Scoreboard
docker compose up -d --build
```

> 仓库是公开的,`git clone` 不需要任何凭据,服务器上也不用存 token。

> **服务器没有外网?** 那就别在服务器上现场构建 —— 构建要联网拉 npm 依赖和基础镜像。
> 在你自己(有外网)的机器上打一个离线部署包,拷过去直接 `docker load`:
>
> ```bash
> npm run package:docker          # 产出 dist/:镜像 tar + compose + 部署说明
> scp -r dist user@server:/opt/biph/
> # 服务器上:docker load -i biph-0.1.0-linux-amd64.tar && docker compose up -d
> ```
>
> **以后更新**(服务器已 clone 过仓库):
>
> ```bash
> cd /opt/BIPH-Scoreboard
> ./scripts/deploy.sh              # 拉代码 → 重建镜像 → 重启 → 打印状态和日志
> ./scripts/deploy.sh --rollback v0.1.0    # 回滚到某个版本
> ```
>
> 完整的打包、备份、迁移、故障排查见 **[docs/DEPLOY.md](docs/DEPLOY.md)**。

启动后日志里会打印局域网访问地址:

```
BIPH 场地管理台 已启动  https://192.168.1.20:8080
   https://192.168.1.20:8080
   管理员密钥: (默认值)
```

### 2. 管理员密钥 = `1818`

**默认就是 `1818`**,不用去服务器上翻任何文件。配置页点「重置比赛」或「删除比赛」时,
会弹出输入框,填 `1818` 即可。

```
管理员密钥: 1818
```

> 这个密钥防的是**误触**,不是黑客 —— 校内封闭网络里,现场真正要挡的
> 是"手滑把正在打的比赛删了"。所以它写死、明着写在文档和弹窗提示里。
> 密钥输错时弹窗**不关**,原地告诉你"需要管理员密钥",改一个字符就能再试。
>
> 想更严就自己在部署时改(`docker-compose.yml` 的 `environment` 里加一行):
>
> ```yaml
> environment:
>   ADMIN_KEY: "你自己的密钥"
> ```
>
> 改完 `docker compose up -d` 重建容器即可,弹窗提示会照旧告诉现场用哪个。

### 3. 分清两把钥匙,现场才不会卡住

| 钥匙 | 管什么 | 你什么时候需要它 |
|---|---|---|
| **控制令牌** operatorToken | 连控制台计分/计时;**改本场参数**(队名、规则、显示设置) | 计分员开赛与调参时 —— 已包含在控制台二维码与链接里 |
| **管理员密钥** adminKey | **重置比赛、删除比赛**(不可逆的破坏性操作) | 只有你要**重置或删除**时 —— 默认 `1818` |

**控制比赛、调本场参数,都不需要管理员密钥。** 计分员扫一下「控制台二维码」就能直接开打,
比赛进行中要改进攻钟秒数,回「比赛配置」页改完点顶栏**保存**即可(顶栏会一直显示
「未保存修改 / 已保存」,不会让你以为没生效)。
**开关类选项(使用进攻钟、大屏显示犯规/暂停/进攻权、大屏模板……)勾上就立即生效**,大屏同步更新。
就算没带二维码,打开控制台页面点「**自动获取控制令牌**」也能自己取到。

### 4. 现场使用

1. 打开管理台 `https://<服务器IP>:8080/` → 新建比赛(队名、场地号、规则参数)
2. 进「比赛配置」→ 打印控制台二维码,给计分员的 iPad 扫码
3. 大屏设备打开显示链接(`/m/<id>/display`),全屏
4. iPad 上开始记分

## HTTPS 与 iPad(重要)

iPad Safari 的 **Service Worker**(PWA 离线外壳)与 **Wake Lock**(防锁屏)都要求**安全上下文**。
纯 `http://192.168.x.x` 下两者全部失效 —— 而 Wake Lock 一失效,**计分员的手机会在比赛中途锁屏**。

所以默认开启 HTTPS(自签证书,含局域网 IP 的 SAN)。首次用 iPad 访问会提示证书不受信任,需要:

> 设置 → 通用 → 关于本机 → 证书信任设置 → 打开对应证书的完全信任开关

### ⚠️ 用 Docker 部署必看:`CERT_NAMES` 不填,控制台一定连不上

自签证书的 SAN 来自 `os.networkInterfaces()`。在 Docker 里它只能看到**容器自己的网卡**(172.x),
看不到宿主机的 IP,于是浏览器会报**证书名称不匹配**:

- 页面:点「继续前往」还能看
- **控制台的 WebSocket:同样被拦,而且没有「继续前往」可点 → 永远「连接中断」**
- 大屏其实也连不上,只是有 REST 兜底,比分照常显示,所以不容易发现

```yaml
# docker-compose.yml —— 换成你的宿主机 IP
environment:
  CERT_NAMES: "10.37.2.208"
```

```bash
# 旧证书缓存在数据卷里不会自动重签,删掉再重启
docker compose exec scoreboard sh -c 'rm -f /data/cert/server.crt /data/cert/server.key'
docker compose up -d
```

> 验证时要看 **`IP Address:10.37.2.208`**,不是 `DNS:10.37.2.208`。
> 证书的 SAN 分两种条目:`DNS:` 只匹配主机名,`IP Address:` 才匹配 IP 地址;
> 浏览器拿 IP 访问时只认后者(RFC 6125),写成 `DNS:` 等于没写。

> **更好的做法**:让学校 IT 签发 `scoreboard.xxx.edu` 的证书,挂进来即可:
> ```yaml
> environment:
>   CERT_NAMES: "scoreboard.school.edu"
> ```
> 证书文件放 `/data/cert/server.key` 与 `/data/cert/server.crt`(存在则自动复用)。

若 iPad 版本低于 iOS 16.4(无 Wake Lock),系统会自动退化为「静音音频循环」兜底方案,不会锁屏。

## 校园网注意事项

| 问题 | 现象 | 对策 |
|---|---|---|
| **AP 隔离** | 手机访问不到同网段的服务器 | ① 用独立热点/自带路由器;② `docker-compose.yml` 里改用 `network_mode: host`(Linux);③ 把服务器和 iPad 接到同一台交换机 |
| **IP 变动** | 重启后地址变了,二维码失效 | 给服务器配 DHCP 静态绑定,或用固定域名 |
| **端口被拦** | 只能开 80/443 | 把 `ports` 改成 `"443:8080"`,或反代到 443 |
| **无外网** | 正常,零外部依赖 | 字体全部本地内置,不请求任何外部域名 |

## 架构

```
  ┌──────────────┐  WebSocket   ┌─────────────────────────┐
  │ 计分员 iPad  │ ────────────▶ │   BIPH 场地管理台 Server (单容器)  │
  │ 控制台 PWA    │ ◀──────────── │   ├─ WS  /ws/:matchId   │
  └──────────────┘  状态 + 1s心跳 │   ├─ HTTP /api/*        │
                                 │   └─ SQLite (WAL) /data │
  ┌──────────────┐  WebSocket   │                         │
  │ 大屏 / 投影   │ ────────────▶ │                         │
  └──────────────┘               └─────────────────────────┘
```

- **TypeScript** 全栈:`Fastify` + `ws` + `node:sqlite` + `React`/`Vite`
- **单容器**、零外部服务(SQLite 用 Node 内置模块,无原生编译)
- 前端产物由后端进程托管,单端口对外

### 时钟同步

```
服务端:锚点 { running, remainingMs, anchorServerTs }
        服务器时钟 = 启动墙钟 + 单调时钟增量(不受 NTP 影响)
客户端:收到消息 → 记录 (serverTs, performance.now())
        当前服务器时间 ≈ serverTs + (performance.now() - 接收时刻)
        剩余时间 = remainingMs - (当前服务器时间 - anchorServerTs)
```

核心性质:**任意一条消息单独都能算出此刻应显示什么**。

### 命令回执(提示为什么不会说假话)

```
控制台 --cmd(cmdId)--> 服务端
控制台 <--ack(cmdId, ok, error?)-- 服务端
```

服务端对**每一条**命令回一条 `ack`:`ok=true` 表示这条命令确实执行了,`ok=false` 时 `error` 是中文原因
(如「暂停已用完」「没有可撤销的操作」)。控制台的右上角提示**只根据这条回执弹**:

- `ok=true` → 绿色对勾,写清楚做了什么(例如「猛虎联队 +2 分」)
- `ok=false` → 红色,把服务端给的原因原样翻译出来

提示里**只写动作,不写动作之后的比分** —— 连点时服务端的广播还没回来,写进去的就是个假数字。

### 用编译产物跑(与容器内完全一致)

`npm run build` 之后直接跑编译出来的后端,跟 Docker 里的 `node server/dist/index.js` 是同一条路径:

```powershell
cd BIPH-Scoreboard
npm run build
$env:PORT='8080'; $env:HOST='0.0.0.0'; $env:DATA_DIR="$PWD\data"; $env:HTTPS='true'
node server\dist\index.js
```

> Windows 上如果想让它在后台常驻,记得用 `Start-Process` 启动并把 PID 记下来,方便随时停:
> ```powershell
> $p = Start-Process node -ArgumentList 'server\dist\index.js' -WorkingDirectory $PWD -PassThru -WindowStyle Hidden
> $p.Id | Out-File -Encoding ascii "$PWD\server.pid"
> # 停止
> Stop-Process -Id (Get-Content "$PWD\server.pid")
> ```

前端产物目录是**自动探测**的(`client/dist` 会在源码目录、编译目录、容器布局之间自动找),
也可以用 `CLIENT_DIR` 环境变量显式指定。

### 浏览器级断网验证(实测)

在真实 Chromium 里用 CDP `Network.emulateNetworkConditions` 把大屏页**真的断网**,
再把页面显示值与服务端锚点算出的真值逐秒比对:

| 时刻 | 页面显示 | 服务端真值 | 偏差 |
|---|---|---|---|
| 在线 | 425s | 425s | **0s** |
| 断网 5 秒后 | 420s | 420s | **0s** |
| 恢复网络后 | 416s | 416s | **0s** |

即:断网期间时钟照常走秒,且**始终与服务端真值完全一致**;恢复网络后自动重新同步。

### 浏览器级暂停倒计时提示验证(实测)

在真实 Chrome 里用 CDP 打开控制台页、逐帧读回 `.timeout-alert` 的**真实 DOM 文本**
(暂停时长临时设成 20 秒,好观察):

| 时刻 | 控制台顶部横幅的真实文本 |
|---|---|
| 暂停刚开始 | 无横幅 |
| 剩 5 秒 | 红色 `⏱ 暂停倒计时 5 秒后结束` |
| 剩 4 秒 | 红色 `⏱ 暂停倒计时 4 秒后结束` |
| 剩 3 秒 | 红色 `⏱ 暂停倒计时 3 秒后结束` |
| 剩 2 秒 | 红色 `⏱ 暂停倒计时 2 秒后结束` |
| 剩 1 秒 | 红色 `⏱ 暂停倒计时 1 秒后结束` |
| 归零 | 绿色 `✓ 暂停时间结束,请准备开赛` |
| 再过 3 秒 | 横幅自动撤下 |

两个边界同样实测过:

| 场景 | 结果 |
|---|---|
| 剩 15 秒时按「继续比赛」 | **不弹**结束提示(提前结束不算"时间到") |
| 剩 3 秒时按「继续比赛」 | **仍弹**「暂停时间结束」(此刻倒计时确实已到点) |

### 浏览器级开赛倒计时验证(实测)

在真实 Chrome 里用 CDP 打开大屏页,读回 `.board-startup` 的真实文本与七段管的 `aria-label`
(开赛时间临时设成"此刻之后 2.5 分钟",好观察):

| 时刻 | 大屏上的真实内容 |
|---|---|
| 开赛时间 12:15、机器时间 12:13:00 | `距开赛` + 七段管 `02:00` + `12:15 开赛` |
| 16 秒后再看 | 七段管 `01:44` —— **读秒在走** |
| 待机层 `.board-standby` | **不存在**(倒计时这一屏取代了它,两层不叠着挡) |

│   ├── hub.ts              WS 同步中枢
│   ├── db.ts               SQLite 持久层
│   ├── routes.ts           REST 路由
│   ├── certs.ts            自签证书生成
│   └── index.ts            启动入口
├── server/test/            104 项测试(clock / match / config / certs / e2e)
├── client/src/
│   ├── pages/              Dashboard / MatchSetup / Control / Display
│   ├── templates/          simple / led / broadcast 三套大屏模板(共用一套 DOM)
│   ├── components/         SevenSegment / ToastStack / TimeoutAlert / AdminKeyPrompt / ServerClock 等

│   └── lib/                api / ws / audio / horn / sports / toasts / timeoutAlert / useWakeLock

├── scripts/package-image.mjs  打包离线部署包(镜像 tar + compose + 部署说明)

├── docs/REQUIREMENTS.md    需求分析文档 v0.17
├── docs/DEPLOY.md          打包与部署手册(离线部署 / 备份 / 迁移 / 排障)
└── docs/scoreboard-analysis.html   可视化分析页
```

- ✅ 中/英界面切换(**整个场馆一个语言**:管理台 / 控制台 / 大屏 / 配置页切一下,全场一起变;二维码仍带 `?lang=` 作首屏兜底)
